# Module 38: IoT Security Regulation — California SB-327 & UK DCMS Code of Practice

## Learning Objectives
- Explain how California SB-327 shifted IoT security from best practice to legal liability, and its unique-password mandate
- Enumerate the UK DCMS Code of Practice's 13 guidelines and its three core pillars
- Understand how both regulations translate into concrete IC design requirements (OTP/PUF unique ID, secure provisioning, HRoT secure boot, debug-port lockdown)
- Trace the regulatory lineage from SB-327 and DCMS to ETSI EN 303 645 and the UK PSTI Act 2022

## Estimated Time
1.5 hours

- Module 04 (PUF & TRNG)
- Module 05 (Secure Boot & Authentication)

## Key Topics
1. SB-327: "reasonable security feature(s)" and the unique-password mandate
2. DCMS Code of Practice: no default passwords, vulnerability disclosure, secure software updates
3. Secure credential storage, software integrity (HRoT/Secure Boot), and attack-surface minimization
4. UK PSTI Act 2022 — from voluntary code to binding law
5. Global regulatory domino effect (ETSI EN 303 645)
