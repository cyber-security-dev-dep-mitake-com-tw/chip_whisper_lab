## Ch1 HW Security Standard & Regulation (硬體安全標準與規範)

### 單元 1.2：Towards FIPS 140-3 (邁向 FIPS 140-3 時代與國際接軌)

#### 1. 為什麼需要更新至 FIPS 140-3？ (The Need for FIPS 140-3)

FIPS 140-2 自 2001 年發布以來，主導了長達近二十年的全球硬體安全模組認證市場。然而，隨著半導體製程的微縮、物聯網（IoT）的爆發，以及旁路攻擊（Side-Channel Attacks, SCA）等非侵入式實體攻擊手法的日新月異，FIPS 140-2 的框架逐漸無法涵蓋現代系統單晶片（SoC）面臨的新型威脅。

為了解決這些侷限性，美國國家標準暨技術研究院（NIST）於 2019 年正式發布了 **FIPS 140-3**。此次更新最具歷史意義的改變，在於它不再是一個僅由美、加兩國獨立維護的標準，而是**全面與國際標準化組織（ISO）接軌**。FIPS 140-3 在核心架構上直接引用了 **ISO/IEC 19790:2012**（密碼模組安全要求）與 **ISO/IEC 24759:2017**（測試要求），這大幅減少了跨國科技企業在全球各國進行硬體安全認證時的重複成本。

#### 2. FIPS 140-3 對 IC 設計的核心影響與改變

對於硬體設計與資安工程師而言，從 FIPS 140-2 轉移至 FIPS 140-3 並非只是文件作業的更新，而是牽涉到矽智財（IP）底層架構的實質要求提升。以下是幾個最關鍵的轉變：

* **非侵入式攻擊（Non-Invasive Attacks）的強制要求：**
在 FIPS 140-2 中，對於差分功耗分析（DPA）或電磁洩漏（EMA）等旁路攻擊的防禦，在核心條文中並未被強制全面規範。然而，在 FIPS 140-3 框架下（具體參考附錄 NIST SP 800-140F），硬體模組必須明確提交針對非侵入式攻擊的緩解（Mitigation）機制與測試證明。這迫使 IC 設計在 RTL 階段就必須導入布林遮蔽（Boolean Masking）或邏輯閘層級的時序/功耗隱藏技術。
* **模組生命週期保證（Life-Cycle Assurance）：**
FIPS 140-3 對於供應鏈安全的管控大幅加嚴。晶片設計公司不僅要保證「最終產品」的安全，更必須證明在整個硬體開發生命週期中（包含版本控制、漏洞修補管理、安全交付與最終產品報廢階段的金鑰撤銷）皆符合嚴格的安全工程流程。
* **更嚴密的歸零機制（Zeroization）：**
當硬體防篡改電路偵測到物理入侵時，晶片必須將關鍵安全參數（CSP，如明文金鑰）徹底抹除。FIPS 140-3 對於「歸零」的定義與測試方法更加嚴格，確保攻擊者無法從靜態隨機存取記憶體（SRAM）的物理殘留電荷中還原出金鑰資料。

#### 3. FIPS 140-2 與 FIPS 140-3 的關鍵差異比較

| 評估維度 | FIPS 140-2 | FIPS 140-3 |
| --- | --- | --- |
| **國際標準接軌** | 美國與加拿大主導的獨立標準 | 完全整合 ISO/IEC 19790 與 ISO/IEC 24759 |
| **附錄與技術規範** | 直接附於 FIPS 140-2 主文件中 | 拆分為一系列 NIST SP 800-140 系列指南，便於因應新技術快速更新 |
| **旁路攻擊 (SCA) 防禦** | 非核心強制要求（視特定測試實驗室或應用而定） | 成為獨立且明確的評估項目（強烈依賴 NIST SP 800-140F 規範） |
| **軟體與韌體安全** | 要求相對基礎，缺乏現代安全編碼規範驗證 | 強化對韌體完整性驗證及可信賴執行環境（TEE）運作邊界的要求 |

#### 4. 模組過渡與日落條款 (Transition Timeline)

資安標準的演進伴隨著強制性的汰換時程。NIST 旗下的密碼模組驗證計畫（CMVP）已於 2021 年停止接受新的 FIPS 140-2 申請案。所有新開發的晶片級信任根（HRoT）、硬體安全模組（HSM）與加密協同處理器，目前皆必須依循 FIPS 140-3 規範進行設計與認證。而現存有效的 FIPS 140-2 證書，最晚也將於 2026 年底被全面移至歷史清單（Historical List），這宣告了全球硬體安全供應鏈已正式進入 140-3 的高標準時代。
