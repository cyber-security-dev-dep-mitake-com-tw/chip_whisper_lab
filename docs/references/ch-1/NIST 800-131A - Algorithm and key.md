
## Ch1 HW Security Standard & Regulation (硬體安全標準與規範)

### 單元 1.5：NIST 800-131A - Algorithm and key (密碼學演算法與金鑰長度之過渡與規範)

#### 1. 什麼是 NIST SP 800-131A？

密碼學演算法的安全性並非永恆不變。隨著摩爾定律推動的硬體運算能力提升（如 GPU 平行運算叢集、ASIC 密碼破解機的普及）以及密碼分析數學理論的突破，過去被認為「安全」的演算法與金鑰長度會逐漸變得脆弱。

**NIST SP 800-131A（Transitioning the Use of Cryptographic Algorithms and Key Lengths）** 是美國國家標準暨技術研究院（NIST）發布的一份極具約束力的技術指南。該指南明確規定了聯邦政府與依循 FIPS 140 認證的企業，必須在「何時」以及「如何」逐步淘汰老舊的密碼學演算法，並強制規定了不同應用場景下所允許使用的「最低金鑰強度」。

#### 2. 核心評估指標：安全強度 (Security Strength)

NIST 在評估密碼系統時，引入了「安全強度（Security Strength）」的概念，其單位為位元（Bits）。安全強度代表著攻擊者需要執行多少次運算才能攻破該密碼系統（例如，112 位元的安全強度，意味著破解難度約等於進行 $2^{112}$ 次運算）。

根據 NIST SP 800-131A 與相關指南（如 SP 800-57）的定義：

* **80-bit 安全強度：** 已於 2010 年底全面被業界淘汰，不再視為安全。
* **112-bit 安全強度：** 目前的「最低容許底線」。但通常僅被允許用於解密歷史資料（Legacy Use），不建議用於新系統的防護。
* **128-bit 安全強度（含以上）：** 現代晶片與系統設計的**強制標準**。所有新部署的資安架構，其金鑰與演算法搭配必須提供至少 128 位元的安全強度，以應對直至 2030 年代以後的傳統運算威脅。

#### 3. 關鍵演算法與金鑰長度的退場與過渡規範

NIST SP 800-131A 針對對稱式加密、非對稱式加密與雜湊函數，制定了嚴格的退場時間表：

1. **對稱式演算法 (Symmetric Algorithms)：**
* **禁用的演算法：** 雙金鑰三重資料加密標準（2-Key TDEA / 2TDEA）僅提供 80-bit 安全強度，已遭全面禁用。三金鑰三重資料加密標準（3TDEA）雖提供 112-bit 強度，但也已於 2023 年底被正式淘汰（Disallowed）。
* **強制轉向：** 現代硬體必須全面採用進階加密標準（AES），包含 AES-128、AES-192 與 AES-256，它們分別提供 128、192 與 256 位元的安全強度。


2. **非對稱式/公鑰演算法 (Asymmetric / Public Key Algorithms)：**
* **RSA 與 DSA：** 金鑰長度為 1024-bit 的 RSA（僅提供 80-bit 強度）已被嚴格禁用於數位簽章的產生。目前的新設計中，RSA 金鑰長度必須至少為 **2048-bit**（提供 112-bit 強度），而業界最佳實踐則強烈建議採用 **3072-bit** 或 **4096-bit**（提供 128-bit 以上強度）。
* **橢圓曲線密碼學 (ECC / ECDSA)：** 由於 ECC 具備較短金鑰便能提供高強度的特性，規範要求至少必須使用曲線長度為 **256-bit**（如 NIST P-256，提供 128-bit 安全強度）的演算法。


3. **密碼雜湊函數 (Cryptographic Hash Functions)：**
* **SHA-1 淘汰：** SHA-1 的碰撞阻力（Collision Resistance）僅有 80-bit，NIST 已明令禁止其用於數位簽章的產生與憑證簽發。
* **強制轉向：** 硬體與韌體必須遷移至 SHA-2 家族（SHA-224, SHA-256, SHA-384, SHA-512）或次世代的 SHA-3 系列演算法。



#### 4. 規範對 IC 晶片設計的直接衝擊

對於系統單晶片（SoC）設計工程師而言，NIST SP 800-131A 的過渡時間表對矽智財（IP）的選用與硬體架構配置具有絕對的指導意義：

* **矽智財的精簡與合規：**
在設計硬體密碼學加速器（Cryptographic Accelerators）時，設計團隊應徹底移除對老舊演算法（如 DES、SHA-1）的硬體支援邏輯閘。這不僅能節省寶貴的晶片面積（Silicon Area）並降低功耗，更能避免因保留弱演算法而導致 FIPS 140-3 認證失敗的合規性風險。
* **硬體資源的擴充：**
隨著 RSA 金鑰長度從 1024-bit 躍升至 2048-bit 甚至 4096-bit，硬體內部的大數模運算器（Modular Multiplier）所需的暫存器寬度、內部安全靜態記憶體（Secure SRAM）容量，以及資料匯流排的頻寬皆必須相應倍增。
* **晶片生命週期之前瞻性 (Future-Proofing)：**
車用晶片或工業物聯網（IIoT）設備的生命週期往往長達 10 至 15 年。若 IC 設計時僅踩著 112-bit 的底線，該產品在服役期間極可能遭到法規強制淘汰。因此，具備前瞻性的硬體架構，應在流片前直接將 128-bit（甚至 256-bit，如抗量子運算的預備）作為硬體信任根的基準安全強度。
