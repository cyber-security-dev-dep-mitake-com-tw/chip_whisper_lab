

## 專題補充：熵源 (Entropy Source) —— 物理與軟體機制的深度解析

### 1. 什麼是熵 (Entropy)？密碼學的絕對基石

在資訊理論中，由克勞德·夏農（Claude Shannon）提出的「香農熵（Shannon Entropy）」是用來量化「資訊的不確定性」或「不可預測性」。
如果一個二進位系統（輸出 `0` 或 `1`）完全可以被預測（例如永遠輸出 `0`），它的熵值為 0。如果它輸出 `0` 和 `1` 的機率皆為完美且獨立的 $50\%$，那麼它每個位元（bit）的熵值就是 1。

**為什麼資安需要高熵值？**
所有的密碼學協定——無論是 TLS 握手、產生 AES 根金鑰，還是抵禦重播攻擊的 Nonce——其安全性皆建立在「攻擊者無法猜測出這串數字」的假設上。提供這種不可預測性的源頭，就是**熵源 (Entropy Source)**。

## 第一部分：硬體/物理熵源 (Hardware / Physical Entropy Sources)

物理熵源是建構**真隨機亂數產生器 (TRNG, True Random Number Generator)** 的基礎。它利用微觀世界中無法被決定論物理學準確預測的隨機物理現象來產生亂數。

### 1. 核心物理機制

在 IC 設計中，最常見的物理熵源通常源自於以下幾種現象：

* **熱雜訊 (Thermal Noise / Johnson-Nyquist Noise)：**
這是導體內部電子因為熱能產生隨機熱運動而引起的電壓波動。只要溫度高於絕對零度，熱雜訊就必然存在。它的頻譜是平坦的（白雜訊），且完全符合常態分佈，是密碼學上極度優質的熵源。
* **環形振盪器相位抖動 (Ring Oscillator Phase Jitter)：**
這是目前數位 SoC 中最廣泛使用的 TRNG 實作方式。由奇數個反相器串聯而成的環形振盪器，其振盪頻率理論上是固定的。然而，受到矽晶片內部電晶體熱雜訊與閃爍雜訊（Flicker Noise）的干擾，其訊號邊緣（Edge）在時間軸上會產生微小且隨機的漂移（Jitter）。透過將一個慢速的 RO 去取樣另一個快速的 RO，就能將這些微小的時間抖動轉換為 `0` 與 `1` 的數位亂數。
* **量子穿隧效應 (Quantum Tunneling)：**
利用先進製程中極薄的閘極氧化層，電子穿隧絕緣層的機率受量子力學控制，具備絕對的隨機性與不可預測性。
* **亞穩態 (Metastability)：**
當正反器（Flip-Flop）的輸入訊號違反了建立時間（Setup Time）時，輸出會短暫進入介於 0 與 1 之間的未知狀態。最終倒向 0 或 1 則完全取決於電路內部的微小熱雜訊，SRAM PUF 便是利用此機制。

### 2. 物理熵源的優缺點

* **優點：** 具備「資訊理論上的安全性（Information-Theoretic Security）」。只要物理定律不變，即使攻擊者擁有無限的運算能力也無法預測下一個輸出的位元。
* **缺點：**
* **產出速率慢：** 物理雜訊的頻寬有限，通常無法直接滿足 CPU 高速加密的需求。
* **易受環境干擾：** 若攻擊者刻意改變環境溫度，或發射極強的電磁波（如頻率注入攻擊），可能會將 RO 的頻率鎖定（Frequency Injection Locking），導致熵值瞬間歸零。

## 第二部分：軟體/非物理熵源 (Software / Non-Physical Entropy Sources)

對於沒有內建專屬 TRNG 晶片的系統（如早期的伺服器或一般的桌上型電腦），作業系統（OS）必須在純軟體環境中「收集」不確定性，這就是軟體熵源。

### 1. 軟體收集熵的機制

作業系統的核心（Kernel）會維護一個「熵池 (Entropy Pool)」。它會不斷收集系統中難以被外部精確預測的非同步事件（Asynchronous Events）作為熵的來源：

* **使用者互動：** 滑鼠移動的軌跡與速度、鍵盤敲擊的時間間隔（毫秒級的延遲）。
* **硬體中斷與驅動程式：** 磁碟機讀寫頭尋軌的時間差、網路卡接收到封包的精確時間戳記（Timestamps）、各項周邊設備引發的 IRQ（中斷請求）時間。
* **系統狀態：** 記憶體配置狀態的微小變動、系統程序排程（Context Switch）的微秒級時間差。

在 Linux 系統中，這些來源會不斷被輸入到 `/dev/random` 與 `/dev/urandom` 的產生器中。

### 2. 軟體熵源的優缺點與威脅

* **優點：** 不需要額外的硬體成本，可在任何通用處理器上實作。
* **缺點與致命傷：**
* **虛擬機（VM）的熵耗盡：** 在雲端環境中，虛擬機沒有真正的滑鼠、鍵盤或硬碟。它們所經歷的中斷都是由 Hypervisor 模擬出來的，這導致虛擬機在剛開機時嚴重缺乏熵。如果在熵不足的情況下產生 SSH 金鑰，可能會導致兩台虛擬機產生出完全相同的私鑰。
* **啟動時間漏洞 (Boot-time Vulnerability)：** 系統剛開機的頭幾秒鐘，使用者還沒移動滑鼠，網路封包也還沒進來。此時的熵池是空的或極度可預測的。若此時強制生成安全金鑰，將非常脆弱。

## 第三部分：從熵源到密碼學金鑰的轉換 (Conditioning)

不管是物理熱雜訊還是軟體鍵盤敲擊，它們產生的原始資料（Raw Data）都不能直接當作密碼學金鑰。因為它們可能存在偏誤（例如鍵盤空白鍵被按的機率特別高，或是物理電路的不對稱導致產生的 `1` 比 `0` 多）。

### 1. 熵調節 (Entropy Conditioning) 與白化 (Whitening)

必須將這些含有雜訊與偏誤的來源輸入到數學演算法中進行「調節」。

* **Von Neumann 提取器：** 一種最傳統的硬體去偏誤邏輯。它將輸入的位元兩兩分組。如果遇到 `01` 就輸出 `1`；遇到 `10` 就輸出 `0`；遇到 `00` 或 `11` 則直接丟棄。這能消除 `0` 與 `1` 比例不均的問題，但會損失大量頻寬。
* **密碼學雜湊函數 (Hash_DF)：** 根據 NIST SP 800-90B 規範，現代系統會將大量的原始物理位元輸入至 AES-CBC-MAC 或 SHA-256 引擎中進行雜湊壓縮。這稱為「熵壓縮（Entropy Compression）」。

### 2. 混合式架構：PRNG / DRBG

因為純實體 TRNG 速度太慢，而純軟體熵源在開機時不安全。現代安全架構（如 FIPS 140-3 要求）採用的是**混合架構**：

1. 晶片內部有一個 **TRNG（物理熵源）**。
2. TRNG 產生一串極高強度的 256-bit 亂數，這稱為**種子 (Seed)**。
3. 將這個種子輸入到一個由演算法構成的**偽隨機亂數產生器 (PRNG / DRBG)** 中（例如 AES-CTR 模式）。
4. PRNG 就像一個高速水泵，利用這個絕對隨機的種子，每秒鐘產生出數 GB 的亂數流供系統使用。
5. 每隔一段時間，系統會重新向物理 TRNG 索取新的種子進行**重新播種 (Reseeding)**，以確保長期安全性。

## 專題補充：NIST SP 800-90B 熵評估的數學模型與量化分析

在硬體安全與密碼學中，我們不能僅憑「感覺」或物理直覺來宣稱一個雜訊源是隨機的。美國國家標準暨技術研究院（NIST）發布的 SP 800-90B 提供了一套嚴格的數學框架，其核心目標只有一個：**為熵源的「不可預測性」計算出一個極度保守的下界（Lower Bound）。**

### 1. 核心評估指標：為何揚棄香農熵，改用「最小熵 (Min-Entropy)」？

在傳統資訊理論中，我們常使用**香農熵 (Shannon Entropy)** 來衡量一個系統的「平均」不確定性。假設一個隨機變數 $X$ 有 $k$ 種可能的輸出，每種輸出的機率為 $p_i$，香農熵定義為：


$$H_{shannon} = -\sum_{i=1}^{k} p_i \log_2(p_i)$$

**然而，密碼學不看「平均」，只看「最壞情況」。**
如果一個硬體亂數產生器（TRNG）在 $99\%$ 的時間輸出完美的隨機數，但在 $1\%$ 的時間因為電路瑕疵固定輸出 `00000000`。在香農熵的計算下，平均值依然很高；但對於攻擊者而言，只要直接猜測那最常出現的 $1\%$，就能輕易破壞加密系統。

因此，NIST 800-90B 強制規定必須使用**最小熵 (Min-Entropy, $H_{min}$)**。其定義僅取決於系統中「最可能出現的那一個輸出（The most likely outcome）」的機率 $p_{max}$：


$$H_{min} = -\log_2(p_{max})$$

* **物理意義：** $H_{min}$ 代表了攻擊者在最佳策略下（也就是永遠猜最常出現的那個數值），第一次猜測就命中的難度。如果 $p_{max} = 1$（完全可預測），則 $H_{min} = 0$；如果 256 種輸出機率皆為 $\frac{1}{256}$，則 $p_{max} = 2^{-8}$，$H_{min} = 8$ bits。

### 2. 評估流程的雙軌機制：IID vs. Non-IID

為了評估硬體熵源，NIST 800-90B 要求開發者從晶片中連續擷取 **1,000,000 個原始樣本（Raw Samples）**，並依照以下雙軌數學模型進行測試：

#### 軌道一：IID 檢定 (獨立同分佈檢驗)

獨立同分佈（Independent and Identically Distributed, IID）是指每一個位元的輸出，都不受前一個位元的影響，且整體的機率分佈不隨時間改變（例如理想的擲硬幣）。

* **數學檢定方法：** 系統會使用排列測試（Permutation Tests）與卡方檢定（Chi-Square Test），計算原始序列特徵與「隨機打亂後的序列」特徵之間的差距。
* **若通過 IID 檢定：** 計算極為簡單。找出一百萬個樣本中出現次數最多的數值，計算其機率 $\hat{p}$，並使用二項式分佈的信賴區間求出保守的 $p_{max}$，最後套用 $H_{min} = -\log_2(p_{max})$ 即完成評估。

#### 軌道二：Non-IID 估算 (非獨立同分佈)

在真實的 IC 電路中，由於電壓波動、溫度殘留效應或時脈耦合，物理雜訊通常帶有微弱的「記憶性（Markovian property）」，因此絕大多數的硬體 TRNG 都無法通過 IID 檢定。
對於 Non-IID 序列，NIST 定義了 **10 種不同的數學估算器（Estimators）**，強迫對這一百萬個樣本進行地毯式搜索。

### 3. Non-IID 軌道的關鍵數學估算器 (Estimators)

這 10 種估算器會各自尋找序列中不同的「非隨機規律」，並分別計算出一個預估的最小熵。

1. **馬可夫估算器 (Markov Estimate)：**
假設序列是一個高階馬可夫鏈（Markov Chain）。它計算在已知前 $d$ 個位元的狀態下，預測下一個位元的條件機率。若硬體存在相依性，條件機率會飆高，導致估算出的熵值下降。
2. **碰撞估算器 (Collision Estimate)：**
利用「生日悖論（Birthday Paradox）」的數學原理。它測量在序列中需要讀取多少個樣本，才會遇到第一個「重複的數值（碰撞）」。如果碰撞發生得太頻繁，代表機率分佈集中在少數幾個數值上，$p_{max}$ 會被推高。
3. **LZ78 壓縮估算器 (Compression Estimate)：**
基於 Lempel-Ziv 壓縮演算法的字典生成原理。如果一個硬體雜訊序列可以被大幅度壓縮，代表它包含了大量的重複模式，其不可預測性（熵）必定很低。
4. **最長重複子字串估算器 (LRS / Longest Repeated Substring)：**
搜尋序列中出現過兩次以上的最長連續字串。如果攻擊者發現了一長串固定的模式，這意味著該特定組合的出現機率異常高。

**最終裁定原則（最保守原則）：**
系統會將這 10 個估算器算出的結果排開，並取其中的最小值（Minimum）作為該硬體熵源的最終最小熵 $H_{min}$。例如，即使有 9 個估算器認為熵值高達 $7.5$ bits，但只要壓縮估算器發現規律並給出 $3.2$ bits 的結果，該晶片的最終認證熵值就是 $3.2$ bits。

### 4. 線上健康測試 (Health Tests) 的數學界線

NIST 800-90B 除了要求在實驗室計算出上述的 $H_{min}$，更強制要求在晶片 RTL 中實作即時的健康測試（如 RCT 與 APT）。這些測試的**警報觸發界線（Cutoff Values）**，完全是由 $H_{min}$ 與統計學的假陽性率（False Positive Rate, $\alpha$）透過數學公式推導而來。

以 **重複計數測試 (Repetition Count Test, RCT)** 為例：
RCT 監控是否連續出現同一個數值。假設在實驗室評估出的最壞情況機率為 $p_{max} = 2^{-H_{min}}$，而我們容許硬體因為純粹的機率巧合而發生誤報（False Positive）的機率為 $\alpha$（通常設為 $2^{-30}$ 或更低）。
硬體 RTL 中計數器的觸發上限 $C$ 的計算公式為：


$$C = 1 + \left\lceil \frac{\log_2 \alpha}{\log_2(p_{max})} \right\rceil = 1 + \left\lceil \frac{-\log_2 \alpha}{H_{min}} \right\rceil$$

* **實務意義：** 假設晶片評估出的 $H_{min} = 0.5$ bits/sample，且我們設定誤報率 $\alpha = 2^{-30}$。那麼 $C = 1 + \lceil 30 / 0.5 \rceil = 61$。這意味著，硬體工程師必須在晶片中設計一個計數器，一旦物理熵源連續輸出 61 個完全相同的樣本，硬體就必須判定環境遭到極端干擾（或遭受雷射錯誤注入攻擊），並立即停止供應金鑰。
